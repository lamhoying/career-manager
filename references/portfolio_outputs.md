# Portfolio Outputs（作品集案例库 · 规则真源）

> Aligns to: v2.24.0

**规则真源**：本文件是 `portfolio-outputs/` 目录的**唯一定义源** —— 目录契约 / 案例 schema / 披露分级（L3）/ E19 黑名单 / 索引契约。
`career-dna/` 内任何文件、`references/mode_*.md` 与 `scripts/validate_career_dna.py` **只写指针，不复制规则**。

---

## 1 定位

`portfolio-outputs/` = **跨 JD 长期案例库**。

| 维度 | `portfolio-outputs/` | `resume-outputs/{JD}/` |
|---|---|---|
| 生命周期 | **长期**（跨 JD 累积、反复选取） | **一次性**（随单次投递产生） |
| 单位 | 一个**项目 / 案例**一份 | 一个 **JD** 一套材料 |
| 责任主体 | S1 生成 · S2 刷新 · S3 选取 · S4/S5 合册 | 投递 |
| skill 读取面 | **只读 `.md`，永不读 `.pdf` / `.docx`** | 同 |

> **与 `career-dna/12_portfolio_candidates.md` 的分工**：`12` = **候选池与就绪度**（Readiness / Display Value / Target Track，随 DNA 派生刷新）；本库 = **可投递的案例成品**（书面、可独立阅读）。S3 选取**同时读两者**（见 §6）。

## 2 目录契约

允许的文件形态（**四种，无第五种**）：

| 形态 | 命名 | 约束 |
|---|---|---|
| 索引 | `README.md` | **必含维护钩子**（§6）；不是案例，闸门跳过 |
| 案例 | `{case}.md` | 须含 3 个受控字段（§3）+ 必备节（§3）；受闸门 ②③⑤ |
| 模板 | `{name}_template.md` | 须在索引登记 `kind=template` |
| 其他文档 | `{name}.md` | 非案例的辅助材料 ⇒ 索引登记 `kind=doc`（免 ②③）；**可经「附录区」进合册**（门控见 §7） |

- `{case}` = 受控命名（`snake_case`，与文件名同名）。
- **禁止**写入 `.pdf` / `.docx`（skill 不读二进制；渲染产物落 `deliverables/`）。
- 本目录**不入 manifest**（不是 `career-dna/` 根目录文件，无需四件套）**但必须受闸门约束** —— P2 `portfolio-output-schema`（这是原 F32 的核心缺口）。

## 3 案例 schema

### 3.1 受控字段（头部 `>` 元信息行）

紧跟 `# Portfolio: …` 之后，**三行**，取值受控：

| 字段 | 取值 | 语义 |
|---|---|---|
| `Project` | 项目名（自由短名） | **聚合键** —— 同一项目的所有变体**共用同一值** ⇒ 多变体只算 **1 个**案例 |
| `Variant` | `none` \| 自由短名（建变体时于案例库登记取值域） | **变体级选取键** —— S3 按 JD Track 匹配 |
| `Disclosure` | `对外` \| `面试` \| `内部` | **披露分级**（§4）；`内部` ⇒ 拒绝渲染对外版（fail-safe 硬拦） |

> ⚠️ **与 `07` 身份层的边界**：`Variant` **不是**身份层字段、**不进**任何派生计算、**不表达赛道**（甲案：赛道 ≠ 身份）。它只是**材料的组织维度**。
> ⚠️ **受控化理由**：案例库此前**零闸门**、头部是自由散文 ⇒ **同一项目的三个变体在机制内没有共同主键**，机器无法聚合、无法判「是不是同一个项目」。受控化后才能机械计算「A 级案例数」而不是「文件数」。

### 3.2 必备节（H2）

**唯一定义源 = `assets/templates/resume-outputs/XX_portfolio.md` 的 H2 集合**（模板为真源，**禁在本文件或脚本内另写一份**）。

> **「可替换」节**：模板中**以注释标明「可替换」**的节（当前 = `业务流程分析`）**不计入必备集** —— 非流程类项目可替换为「技术方案对比」/「调研发现」等。
> **变体材料**（`kind=variant`，如算法附录）结构可完全自定义 ⇒ 不受必备节约束。

### 3.3 索引登记

每个文件须在 `README.md` 索引表登记，且索引每行须指向真实文件（**双向一致**，见 §6）；未登记者由闸门 ④ **聚合**报出。

## 4 披露分级（L3 · 出口三档）

| 出口 | 内容 | 规则 |
|---|---|---|
| **对外版**（合册 = 对外） | L1 + L2 + **L3a** | **净化到可公开** |
| **面试版** | L1 + L2 | 允许内部标注（面试现场口头深挖） |
| **内部稿** | 不净化 | 仅自用 |

- **L1** = 结构剥离（删 `<!-- -->` 注释块）
- **L2** = 语义剥离（删 `D0-D3` 标注 / `TC 编号` / 版本注释 / **`口径` 字段** / **`派生自` 字段**）
  - **v2.24.0（F35）补入后两项**：`口径` 在 `Variant: none` 时会印出「**口径：none**」（模板无 `none` 分支）；
    `派生自` 会印**内部文件路径 + 案例库结构**（`portfolio-outputs/{case}.md @日期`）⇒ 二者均**无对外语义**，
    按 **default-open**（举证责任在「排除」侧）显式裁决为**剥离**。
- **L3a** = ① 剥 `[内部]` / `[原设计·汇报稿]` 标注段 ② **E19 黑名单**（§5）机械扫
- ⚠️ **fail-safe**：`Disclosure: 内部` ⇒ **拒绝渲染对外版（硬拦）**。
- **标签策略（对外版）**：**保留** `[实测]` / `[设计]`（可信度信号）；**必须剥** `[内部]` / `[原设计·汇报稿]`。

## 6 索引契约（`README.md`）

「**案例总览**」表列头（加固）：

| 列 | 说明 |
|---|---|
| 文件 | 相对链接 `[x.md](x.md)` —— 双向一致的锚 |
| 案例 | 人类可读名 |
| **kind** | `case` \| `variant` \| `template` \| `doc` —— **闸门按此分派**（② 只约束 `case`） |
| **Project** | 同 §3.1（聚合键） |
| **Variant** | 同 §3.1 |
| **Disclosure** | 同 §3.1 |
| 状态 / Potential / 核心展示能力 / 适用岗位 | 原列（不变） |

**维护钩子（硬约束）**：加列 / 加行后**必须同步**：
1. 每个 `{case}.md` 都在表内；
2. 表内每行文件都存在（无悬空行）；
3. 新增变体须**先在表内登记取值域**（否则闸门 ③ 报警）。
> 「加字段须同时加维护钩子」—— **无钩子 = 第一天即脏**。

**选取源（S3 · `mode_d` §Portfolio Selection）**：`12_portfolio_candidates.md` 的 Ready 池 **+ 本库本赛道口径变体**（`Variant` 按 JD Track 匹配）。变体语义 ≠ 项目候选 ⇒ **单开「补充候选」节，混表会污染计数**。

## 7 附录区（Appendix · `kind=doc` 的收录口 · F40）

**定位**：合册原只收 `case` / `variant`；本区**新开一个收录口**，让 **`kind=doc`**（非案例辅助材料）能以**附录**形态进合册 —— **只在门控命中时**收录，且**不算案例**。

| 维度 | 规则 |
|---|---|
| 收录面 | 本库 `kind=doc` 且**门控命中**的材料（当前唯一实例 = `<实例文档>.md`「<文档标题>」） |
| 受控标记 | 合册 md 中 `## 附录：{名}` —— 判据 = 标题**纯文本**以「附录」起始（受控前缀） |
| 标题适配 | 材料标题须**降一级**：源 H1 **弃** / 源 H2 → `###` / 源 H3 组 → **粗体标签**或并入表格 —— **禁 `#### `**（未定义，退化为正文且不报错） |
| 门控（行业） | **默认**：`JD Track` ∈ **游戏行业赛道白名单**（当前 = `<默认赛道ID>`）｜**覆盖**：Portfolio Gate ③ 可**显式加挂 / 摘除**（覆盖 `<非白名单赛道>` 等、投递 `<目标行业>` 公司的情形） |
| 位置 | **恒置尾**（所有案例之后）；md 书写顺序亦须在最末 |
| 计数 | **不计案例数**、不进 A/B 级计数、不占「≤3 案例」额度 ⇒ 渲染为**独立桶**（不进 `.toc`） |
| 页数 | **计入**体量预算（见 §7.1） |
| 披露 | **同案例**：L1 + L2 + L3a · E19 机械扫（命中即中止）· `Disclosure: 内部` **硬拦** |
| 不升级 | **不**补必备节、**不**进 A/B 候选池、**不**进 S3 选题表；**只读**，不回写本库 |

### 7.1 体量预算（v2.23.2 起）

- **案例 ≤ 3** ／ **总页数 ≤ 12（其中附录区 ≤ 3）** —— 超限 ⇒ Portfolio Gate **显式报页数待放行**
- 附录超 3 页的处置：**㈠** 放宽额度 ／ **㈡** 改用精简版材料（保留画像与定位、删细节）

> **为什么单列而不并入案例**：附录语义 ≠ 案例候选 ⇒ **混桶会污染「A 级案例数」与目录**（同 §6「变体语义 ≠ 项目候选」的纪律）。
> **为什么门控用 `Track` 而不是「行业」**：本 skill 的**机械轴只有 `Track`**；「行业」在 `01_application_index` / `01_jd_match_report` 均为**自由文本** ⇒ 直接拿来做门控 = **不可治理**（「自由文本字段 = 不可治理根因」）。故门控绑受控轴 + Gate 人工覆盖作**白名单外兜底**。
